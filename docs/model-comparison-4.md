# 시나리오 4: 근거 문서(RAG) 유무와 검색 문단 수 (Flash-Lite, Luna × 문서 유무, 14문항)

가상 회사 규정 문서를 검색해 프롬프트에 넣었을 때(RAG)와 문서 없이 답하게 했을 때의 정답률·비용·지연을 비교하고, 검색에 가져오는 문단 수(topK)가 결과에 어떤 영향을 주는지 확인한 결과입니다.

## 한 줄 결론

문서를 넣으면 두 모델 모두 정답률이 약 30%에서 92.9%로 올랐고(신뢰구간이 겹치지 않음), 검색이 놓친 1문항(어휘가 겹치지 않는 질문)을 빼면 모두 맞혔습니다. 가져오는 문단 수를 1에서 5로 늘려도 정답률과 검색 적중률은 같고 비용만 약 1.6배가 되어, 이 평가셋에서는 topK=1이 가장 효율적이었습니다.

## 실험 조건

| 항목 | 내용 |
|---|---|
| 모델 | Gemini 3.1 Flash-Lite, GPT-6 Luna |
| 데이터셋 | `rag-qa` (회사 규정에 관한 14문항. 질문마다 정답과 정답이 적힌 근거 글귀(evidence) 포함) |
| 문서 | 가상 회사 "노바테크"의 규정 문서(테스트용). 빈 줄 기준 문단 단위로 조각냄 |
| 검색 | 앱 내장 BM25(단어 일치 기반) 상위 topK개 문단을 프롬프트의 `{{context}}`에 삽입 |
| 채점 | contains (응답에 정답 문자열이 들어 있으면 정답) |
| 검색 적중률 | 상위 topK개 문단 안에 근거 글귀가 들어 있었던 질문의 비율 |
| 실행 방식 | 조건당 1회, 전부 성공률 100% |

### 질문 구성

| 구분 | 문항 | 설명 |
|---|---|---|
| 일반 | 12문항 | 질문이 문서 표현을 그대로 쓰는 문항 |
| 표현이 다른 문항 | 2문항(13, 14번) | 13번 "새로 들어오면 처음에 어떤 기기를 받나요?"는 문서의 "신규 입사자", "노트북"과 겹치는 단어가 없음. 14번 "몸이 안 좋아서 집에서 일하고 싶으면…"도 재택근무라는 단어가 없음 |

13, 14번은 검색이 어려운 경우를 보려고 일부러 넣었습니다. 따라서 이 14문항은 실제 질문 분포가 아니라 난이도를 섞은 평가셋이며, 적중률 같은 절대값보다 조건 간 비교에 의미가 있습니다.

### 프롬프트

| 프롬프트 | 내용 |
|---|---|
| `rag-무문서` v2 | "질문에 정답만 짧게 답하세요" (모른다고 답할 선택지를 주지 않음) |
| `rag-문서` v3 | `{{context}}`의 발췌만 근거로 답하고, 답이 없으면 "문서에 없음"이라고 답하며, 단위와 표기는 발췌 그대로 쓰도록 지시 |

두 프롬프트에는 차이가 하나 더 있습니다. 문서 쪽에만 "문서에 없음" 선택지가 있어서, 무문서는 사실상 모르는 채로 찍게 한 조건입니다.

## 핵심 지표 해석

### 1. 문서 효과는 크고, 신뢰구간이 겹치지 않는다
Flash-Lite는 28.6%에서 92.9%로(+64.3%p), Luna는 35.7%에서 92.9%로(+57.1%p) 올랐습니다. 문서 있는 쪽의 구간 하한(68.5%)이 문서 없는 쪽의 상한(54.6%, 61.2%)보다 높아서 14문항으로도 우연이라고 보기 어렵습니다. 회사 고유 값을 묻는 9문항은 문서 없이는 전부 0%였습니다.

### 2. 문서 없이 맞힌 문항은 모두 상식이나 관행으로 짐작 가능한 값이다
무문서의 28.6%와 35.7%는 코어타임 10~16시, 연차 15일, 동호회 최소 5명, 신입에게 노트북 지급 같은 흔한 값을 찍은 결과입니다. 조의금 30만, 석식 15,000처럼 회사마다 다른 값은 틀렸습니다. 무문서 정답률은 "모델이 아는 상식의 바닥"이고, 문서 효과는 그 위로 올라가는 폭으로 봐야 합니다.

### 3. 문서를 주면 두 모델의 정답률이 같아진다
Flash-Lite와 Luna 모두 92.9%이고 틀린 문항도 같습니다(13번 하나). 정답률로는 모델 차이가 보이지 않고, 차이는 비용과 지연에 있습니다. Luna는 비용이 약 절반($0.00028 대 $0.00060)이고 Flash-Lite는 지연이 약 절반(798ms 대 1.7s)입니다.

### 4. 검색 문단 수를 늘려도 정답률은 그대로이고 비용만 오른다
topK 1, 3, 5에서 정답률과 적중률이 모두 같았고, 1에서 5로 가면 토큰이 1.8배, 비용이 약 1.6배가 되었습니다. 문항마다 답이 문단 하나에 있고 단어가 겹쳐서 BM25 상위 1개로 충분했기 때문입니다. 여러 문단을 종합해야 하는 질문이나 더 긴 문서에서는 결과가 달라질 수 있습니다.

### 5. 놓친 문항은 문단 수를 늘려도 해결되지 않는다
13번은 질문과 문서가 공유하는 단어가 없어 topK=5에서도 근거 문단을 못 가져왔습니다. 단어 일치 기반 검색은 점수가 0인 문단을 올리지 않으므로, k의 문제가 아니라 검색 방식의 한계입니다. 해결하려면 동의어 확장, 질문 재작성, 임베딩 검색 같은 다른 방식이 필요합니다. 14번은 "까지", "팀장" 같은 단어가 우연히 겹쳐서 적중했습니다.

### 6. 근거를 못 찾았을 때 모델은 모른다고 답했고, 문서가 없을 때는 지어냈다
- 13번(검색 놓침): 두 모델 모두 "문서에 없음"이라고 답했습니다. 지어내지 않았고 프롬프트의 거절 규칙이 동작했습니다.
- 무문서 Luna 3번: "회사 규정을 확인해야 합니다." (회피)
- 무문서 Luna 4번: "보통 50,000원이며, 가까운 사이면 100,000원 이상입니다." 회사가 주는 조의금이 아니라 문상 가서 내는 조의금 상식으로 답한, 틀린 값을 단정한 응답입니다.
- 무문서 Flash-Lite 4번: "50,000원~100,000원"

13번은 무문서에서는 상식으로 맞았고(노트북) 문서 조건에서는 "문서에 없음"이라 오답이었습니다. 문서를 쓰는 쪽이 이 문항에서는 덜 맞지만 더 정직했습니다.

### 7. 비용 방향은 모델마다 달랐다
Luna는 문서를 넣으면 비용이 약 1/4로 줄었고(입력은 늘지만 무문서에서 출력이 길어짐, 무문서 v1 기준 입력 885·출력 2,479토큰), Flash-Lite는 문서를 넣으면 약 1.8배로 늘었습니다(무문서에서도 짧게 답해 입력 증가분만 반영). "RAG가 싸다" 또는 "RAG가 비싸다"로 일반화할 수 없고, 모델이 문서 없이 얼마나 장황해지는지에 달려 있었습니다.

## 평가 설계에서 발견한 문제 (수정 과정)

| 단계 | 발견 | 조치 |
|---|---|---|
| v1 | 10번에서 응답 "14일"이 정답 "2주"와 문자열이 달라 오답 처리(의미는 정답) | 문서 프롬프트에 "단위와 표기는 발췌에 적힌 그대로" 추가(v2) |
| v2 | Flash-Lite가 "300,000원", "1,000,000원"으로 정확히 답했는데 정답 문자열 "30만", "100만"과 달라 오답 처리. 쉼표 규칙 때문 | 쉼표 규칙 삭제 |
| v2 | 프롬프트 예시 `'15,000원'`이 7번(석식 식대) 정답과 같아서, 무문서 Flash-Lite가 5번에 "15,000원"을 베끼고 7번은 예시로 맞힘 | 예시와 규칙을 삭제한 최종 프롬프트(문서 v3, 무문서 v2)로 4런을 다시 실행 |

최종 실행에서 Flash-Lite의 4번, 5번이 100%로 바뀌었고, 무문서 7번이 0%로 내려갔습니다(예시 유출 제거 확인). Flash-Lite 무문서는 정답 문항 수(4개)는 그대로지만 맞힌 문항이 달라졌습니다(7번 대신 5번). 시나리오 2와 같은 교훈입니다. contains 채점은 표기 차이에 민감하고, 프롬프트 예시는 평가 문항과 겹치지 않아야 합니다.

## 한계

- **표본이 작습니다.** 14문항에서 한 문항이 7.1%p이고 모델 2개, 1회 실행입니다. 문서 유무 차이는 신뢰구간이 겹치지 않았지만 topK 간 차이 없음, 모델 간 차이 없음은 "차이를 못 찾았다"는 뜻이지 "차이가 없다"는 뜻은 아닙니다.
- **검색이 쉬운 평가셋입니다.** 12문항은 질문과 답 문단의 단어가 겹치고 답이 문단 하나에 있습니다. 문서도 짧은 편이어서 topK=5는 문서의 상당 부분을 통째로 넣는 효과가 있습니다.
- **어려운 검색은 2문항뿐입니다.** 검색 방식의 한계를 보여 주는 사례일 뿐, 어휘 불일치가 얼마나 흔한지는 측정하지 못했습니다.
- **무문서와 문서 프롬프트가 같지 않습니다.** 문서 쪽에만 "문서에 없음" 선택지가 있어, 무문서는 강제 추측 조건입니다. 무문서에도 모른다고 답할 선택지를 주면 환각 비율이 달라질 수 있습니다.
- **topK 비교는 최종 프롬프트 이전(v2) 실행입니다.** 문서가 정답을 담고 있어 예시 유출의 영향은 없지만, 최종 프롬프트로 다시 돌린 것은 아닙니다.
- **채점이 문자열 포함입니다.** 의미가 맞아도 표기가 다르면 오답이 되므로, 틀린 문항은 응답을 직접 확인했습니다. 두 번 발견했지만 놓친 경우가 더 있을 수 있습니다.
- **14번은 두 가지를 묻는데 한 가지만 채점합니다.** "언제까지 누구에게 말해야 하나요?"의 정답이 "전날 오후 6시"뿐이라, 대상(팀장)을 빼도 100%가 되고 대상만 답하면 0%가 됩니다. 14번의 100%는 시간을 맞혔다는 뜻입니다. 질문을 값 하나만 묻게 고치는 것이 맞지만 실험 전체를 다시 돌려야 해서 그대로 두었습니다.
- **검색 방식이 BM25 하나입니다.** 임베딩 검색이나 재순위화는 비교하지 못했습니다.
- **지연은 참고용입니다.** 실행 시간대가 달라 네트워크 상태가 섞여 있습니다.

## 확인 필요

- 어휘 불일치 문항을 동의어 확장, 질문 재작성, 임베딩 검색으로 풀 수 있는지 확인하기
- 여러 문단이 필요한 질문과 더 긴 문서에서 topK 효과가 달라지는지 확인하기
- 무문서 조건에도 "모르면 모른다고 답하세요"를 넣어 환각 비율(지어낸 답)과 회피 비율을 비교하기
